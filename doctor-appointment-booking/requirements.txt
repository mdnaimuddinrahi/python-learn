DOCTOR APPOINTMENT BOOKING MANAGEMENT SYSTEM
================================================

PROJECT REQUIREMENTS AND SPECIFICATION
======================================


1. PROJECT OVERVIEW
-------------------

The Doctor Appointment Booking Management System is a command-line
application designed to help a small clinic manage doctors, patients,
appointment schedules, and available time slots.

The clinic currently manages appointments manually through phone calls,
messages, or paper records. As the number of doctors and patients increases,
managing appointments manually becomes difficult and can lead to scheduling
mistakes.

The system will provide a simple and organized way to manage doctor
appointments. It will allow clinic staff to create appointments, check
doctor availability, manage cancellations, and view daily schedules.

The first version of the system will be built using Python and will focus
on programming fundamentals, data structures, validation, and business
logic.


2. PROJECT STORY
----------------

A small medical clinic has several doctors who provide different medical
services. Patients contact the clinic to make appointments with a specific
doctor.

Each doctor has their own working schedule. For example, a doctor may work
from 9:00 AM to 1:00 PM and accept appointments every 30 minutes.

The clinic currently records appointments manually. When a patient calls,
the receptionist checks a notebook or existing records to determine whether
the requested doctor and time are available.

As the number of appointments increases, this manual process creates several
problems.

A receptionist may accidentally book two patients with the same doctor at
the same time. It may also be difficult to find a patient's appointment,
check all appointments for a particular day, or identify which time slots
are still available.

The clinic needs a simple system that can manage these activities in an
organized way.

The clinic therefore requests a Doctor Appointment Booking Management
System that can manage doctors, patients, schedules, time slots, and
appointments.


3. PROBLEM STATEMENT
--------------------

The clinic faces the following problems:

1. Appointments are managed manually.
2. It is difficult to check doctor availability quickly.
3. Two patients may accidentally receive the same doctor's time slot.
4. Finding a specific patient's appointment can take time.
5. Cancelled appointments may not be properly tracked.
6. Staff cannot easily see the complete schedule for a doctor.
7. Doctors may have different working hours.
8. Some time slots may need to be blocked because of lunch, meetings,
   emergencies, or other reasons.
9. Maintaining appointment records manually can cause data errors.
10. The clinic needs a simple and consistent way to manage appointment data.


4. PROJECT PURPOSE
------------------

The purpose of the system is to provide a simple appointment management
solution for a small clinic.

The system should help clinic staff:

- Manage doctor information.
- Manage patient information.
- Define doctor working schedules.
- Generate appointment slots dynamically.
- Check available appointment slots.
- Create patient appointments.
- Prevent double bookings.
- View appointment details.
- Search appointments.
- Cancel appointments.
- Block unavailable time slots.
- View a doctor's daily schedule.
- Keep appointment records organized.


5. PROJECT GOALS
----------------

The main goals of the project are:

1. Build a practical Python application based on a real-world problem.
2. Provide a simple way to manage doctor appointments.
3. Prevent appointment conflicts.
4. Make doctor availability easy to check.
5. Keep patient and appointment information organized.
6. Practice Python data structures and business logic.
7. Practice input validation and date/time handling.
8. Build the application in a modular and maintainable way.
9. Create a foundation that can later be extended to use a database or
   web interface.


6. USERS OF THE SYSTEM
----------------------

The first version of the system is intended for clinic staff or a
receptionist.

The staff member will use the application to:

- Add doctors.
- Add patients.
- Manage doctor schedules.
- Check availability.
- Create appointments.
- View appointments.
- Search appointments.
- Cancel appointments.
- Block or unblock time slots.

The system will manage four main types of data:

1. Doctor
2. Patient
3. Doctor Schedule / Time Slot
4. Appointment

    specialization: "Cardiology"

Suggested fields:

- id
- name
- specialization
- phone (optional)
- status

The status can be used to indicate whether a doctor is active.


9. PATIENT DATA
---------------

Each patient should contain basic information.

Example:

Patient:
    id: 1
    name: "John Doe"
    phone: "01712345678"
    age: 32

Suggested fields:

- id
- name
- phone
- age

The first version should store only information necessary for appointment

basic project.


10. DOCTOR WORKING SCHEDULE
---------------------------

Each doctor can have their own working schedule.

For example:

Doctor:
    Dr. Rahman

    Monday

Opening Time:
    09:00

    13:00

    30 minutes

The system can use these settings to generate appointment slots.

Example generated slots:

09:00
09:30
10:00
10:30
11:00
11:30
12:00
12:30


11. DYNAMIC TIME SLOT GENERATION
--------------------------------

Time slots should be generated dynamically from the doctor's working
schedule.

The system should not require every possible time slot to be manually
stored.

For example:

Opening Time: 09:00
Closing Time: 12:00
Slot Duration: 30 minutes

The system generates:

09:00
09:30
10:00
10:30
11:00
11:30

If the slot duration changes to 60 minutes, the system can generate:

09:00
10:00
11:00

This makes the system flexible and reduces unnecessary stored data.


12. SLOT STATUS
---------------

A generated time slot can have one of the following states:

- Available
- Booked
- Blocked

Available:
    The slot can be booked.

Booked:
    The slot has an active appointment.

Blocked:
    The slot cannot be booked because it has been intentionally made
    unavailable.


13. BLOCKED TIME SLOTS
----------------------

A clinic may need to make a time slot unavailable.

For example:

- Doctor's lunch break
- Doctor's meeting
- Emergency situation
- Personal appointment
- Clinic maintenance

Instead of deleting the generated slot, the system should mark it as
blocked.

Example:

09:00 - Available
09:30 - Available
10:00 - Booked
10:30 - Blocked
11:00 - Available

A patient cannot book a blocked slot.

A blocked slot can later be unblocked and become available again.

17. DATA LIFETIME IN VERSION 1
------------------------------

Because the first version uses Python lists and dictionaries, the data will
exist only while the program is running.

When the program is closed, the data will be lost.

This is acceptable for the first learning version because the main purpose
is to practice Python programming, data structures, functions, validation,
and business rules.

Persistent storage can be added in a later version.

21. APPOINTMENT CREATION WORKFLOW
---------------------------------

Example scenario:

A patient named John Doe wants an appointment with Dr. Rahman.

The staff selects:

Doctor:
    Dr. Rahman

Patient:
    John Doe

Date:
    2026-08-10

Time:
    10:00

The system performs the following checks:

1. Does the doctor exist?
2. Does the patient exist?
3. Is the date valid?
4. Does the doctor work on that date?
5. Is the requested time inside the doctor's working hours?
6. Is the time a valid generated slot?
7. Is the slot blocked?
8. Is the slot already occupied by an active appointment?

If all checks pass, the system creates the appointment.

Example result:

Appointment created successfully.

Appointment ID: 1
Patient: John Doe
Doctor: Dr. Rahman
Date: 2026-08-10
Time: 10:00
Status: Confirmed


22. DOUBLE BOOKING RULE
-----------------------

The most important appointment rule is that a doctor cannot have two
active appointments at the same date and time.

For example:

Existing appointment:

Doctor: Dr. Rahman
Date: 2026-08-10
Time: 10:00

If another patient tries to book:

Doctor: Dr. Rahman
Date: 2026-08-10
Time: 10:00

The system must reject the request.

The system should display:

This time slot is already booked for this doctor.


23. IMPORTANT BUSINESS RULES
----------------------------

1. Every doctor must have a unique ID.
2. Every patient must have a unique ID.
3. Every appointment must have a unique ID.
4. A doctor must exist before an appointment can be created.
5. A patient must exist before an appointment can be created.
6. A doctor can have many appointments.
7. A patient can have many appointments.
8. A doctor cannot have two active appointments at the same date and time.
9. A blocked slot cannot be booked.
10. A cancelled appointment does not occupy the time slot.
11. Appointment times must come from the doctor's generated schedule.
12. Appointments cannot be created outside the doctor's working hours.
13. Invalid dates must be rejected.
14. Past dates should not be accepted for new appointments.
15. A cancelled appointment should remain in the records.
16. A blocked slot should not be deleted from the generated schedule.
17. A slot can become available again after an appointment is cancelled.
18. A slot can become available again after it is unblocked.
